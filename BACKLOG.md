# Backlog — transcriptmeter

Single source of truth for what is planned. Items keep a stable `TM-n` id so commits,
the CHANGELOG, the `thoughts/` artifacts and the issues can reference them.

[ROADMAP.md](ROADMAP.md) is a **generated** view of this file — run
`node scripts/backlog.mjs roadmap` after touching it, or CI fails. The GitHub issues are
synced from it one way on every push to `main` that changes this file.

## How to write an item

```
## v0.2.0 — Title of the milestone <!-- ms: phase=next -->

- [ ] **TM-99 — Short name**: what it is, why it earns its place, what it needs to
  touch. <!-- tm: prio=high size=M labels=reader -->
```

- The **id never changes**; a new item takes the next free number.
- `- [ ]` open, `- [x]` shipped with `ver=x.y.z` (or `ver=main` when merged, unreleased);
  decided against → ticked with `ver=dropped` and the reason in the body.
- Labels: `reader`, `metrics`, `benchmark`, `release`, `docs`, `project`, `tests`, `enhancement`.

## v0.1.0 — Numbers you can trust <!-- ms: phase=now -->

The first release: the readers verified against both harnesses' current formats, every
number cross-checked once against an independent source, and the README stating what
the tool cannot know.

**The cross-check is the gate on this milestone.** No `transcriptmeter--v0.1.0` before
one session's totals have been compared with what Claude Code's `/usage` shows for it,
and one Codex session's with Codex's own `/status`, and the differences explained.

- [ ] **TM-1 — Run QRSPI on the brief: Questions → Research → Spec → Plan**: input
  `thoughts/TM-1-transcript-meter/00-brief.md`, one fresh session per phase. The design
  questions it must settle: what "a task" is when it is not a QRSPI phase, how a cache
  miss is attributed to its cause, whether costs on a subscription should be shown at
  all, and how to cross-check totals. <!-- tm: prio=high size=L labels=metrics,benchmark -->
- [x] **TM-2 — Claude Code reader**: sessions from `~/.claude/projects`, usage counted once
  per `requestId`, 5 m and 1 h cache writes, tool results by tool and command prefix,
  QRSPI phase from the first prompt, subagent files flagged, compactions counted.
  <!-- tm: prio=high size=M labels=reader ver=main -->
- [x] **TM-3 — Codex reader**: sessions from `~/.codex/sessions`, `token_usage_record`
  per response with the prompt split into cached and uncached, model from `world_state`,
  exec calls matched to their outputs. <!-- tm: prio=high size=M labels=reader ver=main -->
- [x] **TM-4 — Metrics**: tokens by class, cache hit ratio, misses after a warm prefix,
  model switches, peak context with p50/p95, list-price cost from a dated table with
  unpriced models named, tool output by tool and command.
  <!-- tm: prio=high size=M labels=metrics ver=main -->
- [x] **TM-5 — The CLI**: `summary`, `sessions`, `session`, `tools`, `prices`, `check`;
  `--since`, `--project`, `--harness`, `--no-subagents`, `--roots`, `--json`, `--prices`.
  <!-- tm: prio=med size=S labels=enhancement ver=main -->
- [x] **TM-6 — Fixtures and tests**: synthetic transcripts with the real field shapes,
  regenerated by `test/make-fixtures.mjs`; readers, metrics, renderers and the CLI under
  `node --test`; CI smoke against the fixtures. <!-- tm: prio=med size=S labels=tests ver=main -->
- [x] **TM-7 — Repo operating model**: check, CI on Node 18/20/22/24, release by tag over
  OIDC, Pages from the README, backlog with the one-way issue sync.
  <!-- tm: prio=low size=S labels=project,release ver=main -->
- [ ] **TM-8 — Cross-check the totals**: one Claude Code session against `/usage`, one
  Codex session against `/status`; record both in the README with the differences and
  their reasons. **Gates the release.** <!-- tm: prio=high size=S labels=benchmark -->
- [ ] **TM-9 — Attribute each cache miss to a cause**: model switch, compaction, a gap
  longer than the TTL (from timestamps and the 5 m / 1 h write split), a tool-set change
  (an MCP server appearing in `tool_use` names) — or unknown, counted honestly.
  <!-- tm: prio=med size=M labels=metrics -->
- [ ] **TM-10 — First release 0.1.0**: bootstrap publish, trusted publisher, tag — after
  TM-8. <!-- tm: prio=med size=S labels=release -->
- [x] **TM-14 — Clear the hookgate leftovers**: the repo was started from hookgate's
  scaffolding and kept its wordmark (`hook`·`gate` in the site header), its "Claude Code
  plugin" eyebrow, a hooks inventory read off a `hooks/hooks.json` that does not exist
  here, an `og:image` pointing at a social card nobody had rendered, and release notes
  telling the reader to `/plugin install` and to set `TYPESAFE_API_KEY`. The site now
  derives its wordmark and headline from the README's H1, and the card is rendered from
  `assets/social-preview.html`. <!-- tm: prio=high size=S labels=docs,project ver=main -->
- [x] **TM-15 — `--cap` is the cap that is counted**: the readers counted results over a
  hard-coded 8,000 characters while `tools --cap N` only relabelled that count, so
  `--cap 2000` printed the 8,000 figure under a 2,000 heading, and the line called every
  tool result a shell result. The cap is now an argument to `loadSessions` and the
  readers, the field is `overCap`, and a test reads the same fixtures at three caps.
  <!-- tm: prio=high size=S labels=metrics ver=main -->
- [x] **TM-16 — The corners the audit found**: a `sessions` segment in a path was enough
  to pick the Codex reader, so a `CLAUDE_CONFIG_DIR` containing the word was read with
  the wrong one; an `assistant` entry whose `content` was not a block list lost its usage
  to a guard that ran first; the p50 of an even sample was the upper of the two;
  `make-fixtures` ran inside `node --test` and rewrote the fixtures the tests were about
  to read, so the committed ones were never the ones under test — it now lives in
  `scripts/` and CI fails on a diff. <!-- tm: prio=med size=S labels=tests,project ver=main -->
