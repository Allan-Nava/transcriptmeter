# Backlog — transcriptmeter

Single source of truth for what is planned. Items keep a stable `TM-n` id so commits,
the CHANGELOG, the `thoughts/` artifacts and the issues can reference them.

[ROADMAP.md](ROADMAP.md) is a **generated** view of this file — run
`node scripts/backlog.mjs roadmap` after touching it, or CI fails. The GitHub issues are
synced from it one way on every push to `main` that changes this file.

## How to write an item

```
## v0.2.0 — Title of the milestone <!-- ms: phase=next -->

- [ ] **TM-99 — Short name**: what it is, why it earns its place, what it needs to
  touch. <!-- tm: prio=high size=M labels=reader -->
```

- The **id never changes**; a new item takes the next free number.
- `- [ ]` open, `- [x]` shipped with `ver=x.y.z` (or `ver=main` when merged, unreleased);
  decided against → ticked with `ver=dropped` and the reason in the body.
- Labels: `reader`, `metrics`, `benchmark`, `release`, `docs`, `project`, `tests`, `enhancement`.

## v0.1.0 — Numbers you can trust <!-- ms: phase=now -->

The first release: the readers verified against both harnesses' current formats, every
number cross-checked once against an independent source, and the README stating what
the tool cannot know.

**The cross-check is the gate on this milestone.** No `transcriptmeter--v0.1.0` before
one session's totals have been compared with what Claude Code's `/usage` shows for it,
and one Codex session's with Codex's own `/status`, and the differences explained.

  `thoughts/TM-1-transcript-meter/00-brief.md`, one fresh session per phase. The design
  questions it must settle: what "a task" is when it is not a QRSPI phase, how a cache
  miss is attributed to its cause, whether costs on a subscription should be shown at
  all, and how to cross-check totals. <!-- tm: prio=high size=L labels=metrics,benchmark -->
- [x] **TM-2 — Claude Code reader**: sessions from `~/.claude/projects`, usage counted once
